# kortrade — 관세청 수출 데이터 기반 실적 선행 프록시 파이프라인

한국 수출입 통관 데이터를 자동 수집해 **(1) 어느 섹터가 새로 강해지는지** 판단하고,
**(2) 개별 기업의 분기 실적을 선행 추정**하는 파이프라인. 화장품 섹터를 1차 파일럿으로 구성.

---

## 왜 이게 작동하는가 — 프록시의 성립 근거

관세청 시군구별 수출 통계는 **「제조장소 우편번호」 기준**으로 집계된다.
(출처: [공공데이터포털 API 설명문](https://www.data.go.kr/data/15134343/openapi.do) —
"지역: 수입은 「납세의무자 주소지 우편번호」, 수출은 「제조장소 우편번호」 기준으로 집계")

따라서 `특정 시군구 × 특정 HS6 수출액`은 **그 지역 공장의 출하 실적에 직결**된다.
해당 지역·품목에 공장이 사실상 하나뿐이면, 그 숫자가 곧 그 기업의 수출 실적이다.
파마리서치(강원 강릉)처럼 공장이 한 도시에 몰려 있고 그 도시에 동종 업체가 없는 경우가
프록시가 가장 깨끗하게 성립하는 케이스다.

**공표 시차**: 매월 15일경 전월까지 자료 공표 → 분기 실적 발표보다 **4~6주 선행**.
1~2월 수출이 3월 중순에 나오므로, 1Q 실적 발표(5월 중순) 대비 약 2개월 앞선다.

**주의 — 소급 정정**: 관세청은 신고 정정·취하를 반영해 과거 자료를 현행화한다.
그래서 이 파이프라인은 최근 6개월을 매번 재수집해 UPSERT하고, 값이 바뀐 건은
`revisions` 테이블에 기록한다. "지난달에 본 숫자가 이번달에 바뀌었다"는 사실 자체가 정보다.

## 빠른 시작

```bash
pip install -r requirements.txt
cp .env.example .env && vi .env          # 인증키 입력

export DATA_GO_KR_SERVICE_KEY='...'      # 또는 .env 로드

# 1) 시도코드 표 자동 생성 (최초 1회, 약 100콜)
python scripts/bootstrap_codes.py --post 202608

# 2) 호출량 먼저 확인
python scripts/run_update.py --start 202001 --dry-run

# 3) 수집
python scripts/run_update.py --start 202001

# 4) 리포트
python scripts/report.py rotation
python scripts/report.py country --hs 330499
```

인증키는 [공공데이터포털](https://www.data.go.kr)에서 아래 API를 **활용신청**(개발단계 자동승인)하면
발급된다. 목록은 `.env.example` 참조. 개발계정 트래픽은 **일 10,000콜**(본 클라이언트는 9,000 예산 사용).

## 파일럿 1번 과제: 파마리서치 / 강릉

**아직 확정되지 않은 것**: 리쥬란은 화장품이 아니라 **조직수복용생체재료(의료기기)** 다.
따라서 HS 33류(화장품)가 아닌 30류로 신고될 가능성이 높다. 반면 화장품 라인(리쥬란 코스메틱, 디셀)은
33류이되 ODM 외주 생산이면 강릉이 아닌 다른 시군구로 집계된다.
**어느 HS 코드에 신호가 실려 있는지는 추측이 아니라 데이터로 확정해야 한다.**

```bash
# 강릉시에서 어떤 HS 코드로 수출이 나가는지 역탐색 (core + probe 29개 코드 스캔)
python scripts/discover_hs.py --mode what --sido 강원 --sigungu 강릉시 --start 202001

# 나온 상위 코드의 신호 순도 진단 (전국 대비 강릉 비중, HHI, 월평균 신고건수)
python scripts/report.py purity --hs 330499 --sigungu 강릉시

# 반대 방향: HS 330499 가 전국 어느 시군구에서 나가는지
python scripts/discover_hs.py --mode where --hs 330499 --sido 경기 충북 세종 강원 --start 202301
```

`purity` 진단이 A등급(1위 비중 ≥70%, HHI ≥0.5)으로 나오면 금액 레벨을 그대로 기업 프록시로 쓸 수 있다.
B등급이면 방향성(YoY·가속)만, C등급이면 기업 귀속 없이 지역 총계로만 쓴다.

그다음 분기 실적을 붙여 **선행성을 통계적으로 검증**한다:

```python
from kortrade.store import Store
from kortrade import kpi

st = Store("data/kortrade.sqlite")
kpi.load_kpi_csv(st, "파마리서치_분기실적.csv", company="파마리서치", source="DART")
```
```bash
python scripts/report.py leadlag --company 파마리서치 --metric 매출액
```

CSV 형식: `period,metric,value[,unit]` / `period` 는 `2024-Q1` 형식.

`leadlag` 는 lag 0~3분기 각각의 상관·R²·회귀계수를 내고, **n≥8 & R²≥0.3** 을 통과한
lag 중 최선을 채택한다. 하나도 통과하지 못하면 **"쓸 근거 없음"** 을 명시하고 멈춘다.
프록시는 그럴듯해서 쓰는 게 아니라 과거 구간에서 성립했기 때문에 쓴다.

채택되면 진행 중인 분기의 부분 데이터로 나우캐스트를 낸다. 진척률은 단순 n/3이 아니라
**과거 3년 같은 분기의 실제 월별 배분 중앙값**을 쓴다(분기 말 집중 출하 패턴 보정).

## 섹터 로테이션 판단

```bash
python scripts/report.py rotation                  # 전세계
python scripts/report.py rotation --country US     # 특정 시장
```

세 지표를 z-표준화해 합성한다:

| 지표 | 의미 | 가중 |
|---|---|---|
| `가속_%p` | 최근 3M YoY − 직전 3M 구간 YoY | 0.45 |
| `비중변화_%p` | 섹터 내 점유율 변화 | 0.35 |
| `z12` | 최근 월이 과거 12개월 분포에서 몇 σ | 0.20 |

**레벨(YoY)이 아니라 가속을 1순위로 본 이유**: 높은 성장률 자체는 이미 알려져 가격에 반영돼 있다.
새로 꺾여 올라오는 구간이 알파다. 최근 3개월 수출 300만 달러 미만은 노이즈로 보고 제외한다.

## 자동 갱신 사이트

매월 공표 직후 **수집 → 집계 → 배포**가 무인으로 돌아간다. 구축 절차는
**[SETUP-GITHUB.md](SETUP-GITHUB.md)** 참조.

```
매월 17일 07:00 KST · GitHub Actions
  run_update.py --sectors all  →  build_site.py  →  git commit  →  Pages 배포
                                                        ↓
                                        https://<계정>.github.io/<레포>/
```

**왜 GitHub Actions인가**: Claude 클라우드 환경은 `data.go.kr` 로 나가는 트래픽이
정책상 차단되어 예약 작업으로 수집할 수 없다. Actions 러너는 제한이 없다.

로컬에서 돌리려면:

```bash
# crontab -e  — 매월 17일 07:00
0 7 17 * * cd /path/to/kortrade && python3 scripts/run_update.py --sectors all \
  && python3 scripts/build_site.py >> logs/update.log 2>&1
```

2회차부터는 `fetch_log` 로 확정 구간을 건너뛰므로 실제 호출은 최근 6개월분 + 신규 1개월분뿐이다.

### 멀티섹터

섹터 하나 = `config/sectors/<key>.yaml` 하나. 코드 수정 없이 탭이 늘어난다.

| 섹터 | status | 비고 |
|---|---|---|
| `cosmetics` | **active** | HS 33류 8개 세번, 검증 완료 |
| `semiconductor` | draft | HS 코드 미검증 — `discover_hs.py` 확인 후 승격 |
| `battery` | draft | 양극재·음극재·분리막 분류가 가장 불확실 |

`draft` 는 수집에서 제외되고 사이트에 "미수집" 탭으로만 나타난다. 검증 안 된 코드로
수집하면 빈 데이터나 엉뚱한 품목이 조용히 쌓이기 때문에 기본값을 draft로 뒀다.

## 검증

```bash
python tests/test_pipeline.py     # 또는 python -m pytest tests/ -q
```

API 호출 없이 14건을 검증한다. 의미 있는 것만 꼽으면:

- **소급 정정 감지**: 같은 데이터 재수집 시 `unchanged`, 값이 바뀌면 `updated` + `revisions` 기록
- **선행성 식별**: lag=1 선행 구조를 심은 합성 데이터에서 `best_lag`가 1을 정확히 집어냄 (R²=0.97)
- **오탐 방지**: 상관 없는 난수 계열에서는 `best_lag`가 `None` 반환 → 없는 선행성을 만들어내지 않음
- **계절성 보정**: 분기 말 집중 출하(20:30:50) 패턴에서 2개월차 누적 200 → 분기 400 추정
  (단순 n/3이면 300으로 25% 과소추정)
- **공표 시차**: 2026-09-16 기준 최신 조회 가능월 = 2026-08

## 실데이터 검증 결과 (2026-09 실행)

실제 호출로 확인된 사실. **스펙 문서에 없고 데이터를 봐야만 알 수 있는 것들이라, 모르면 조용히 틀린다.**

| 항목 | 내용 | 놓쳤을 때의 결과 |
|---|---|---|
| **금액 단위** | 시군구/시도 API = **천 달러**, 품목별 API = **달러** | 두 레이어 비교가 1000배 틀어짐 |
| **총계 행** | 응답에 `기간='총계'`, `HS='-'` 행이 섞여 옴 | 합계가 2배로 부풀음 |
| **HS 자릿수** | `hsSgn=330499`로 요청해도 `3304991000` 등 **10단위로 쪼개서** 응답 | 6단위 조인이 전부 실패 |
| **시군구명** | `sggNm` = `"강원특별자치도 강릉시"` (시도명 접두) | 이름 매칭 전부 실패 |
| **시도코드** | **42(강원도)·45(전라북도)는 존재하지 않음** → 51·52 | `resultCode 99 존재하지 않는 시도코드` |

단위 검증 방법: 330499 / 2025-01 을 17개 시도 시군구 합계로 구한 값 **562,366**(천$) vs
품목별 API 전국 값 **562,368,250**($) → 정확히 1000배. 시군구 합계 = 전국 합계이므로 누락도 없다.

확정된 시도코드 17개:

```

43 충북  44 충남  46 전남  47 경북  48 경남  50 제주  51 강원  52 전북
```

### 파일럿 결과 — 강릉시 / 파마리서치

강원(51) × 후보 HS6 14개를 2025년 전체로 스캔한 결과, 강릉시 수출은 **330499 단독 집중**:

| HS6 | 품목 | 강릉 2025 수출 |
|---|---|---|
| **330499** | 기초화장품 | **$85.3M** |
| 330790 | 33류 기타 | $2.3M |
| 300490 | 기타 의약품 | $0.8M |
| **300610** | 조직수복용생체재료 | **$0** |

당초 리쥬란이 의료기기라 30류일 것으로 봤으나, **300610 강릉 수출은 0**이다.
리쥬란 계열이 330499로 신고되거나 화장품 라인이 강릉에서 직접 수출되는 것이고,
어느 쪽이든 **추적 코드는 330499 하나로 족하다**.

```
2019 $3.3M → 2022 $6.6M → 2023 $20.2M → 2024 $33.4M → 2025 $85.3M
2026 1–8월 $86.8M (이미 2025 연간 초과)
2026 1–8월 YoY +67.0% | 최근 3M YoY +88.4% | 가속 +28.6%p
2026-Q3 나우캐스트: 2개월 실적 $23.9M, 계절 진척률 0.646 → 분기 $37.1M 추정
```

대조군으로 춘천시 300212(보툴리눔 톡신 추정, 휴젤)는 최근 3M YoY **-1.3%** 로 정체다.
같은 강원도, 같은 에스테틱인데 방향이 갈린다.

**순도에 대한 정직한 한계**: 이 숫자는 '강릉시 330499 수출액'이지 '파마리서치 수출액'이 아니다.
강릉 내 타사 비중은 API 로 분리할 수 없다. 간접 근거는 월 수출신고 건수뿐인데
(2019년 20건대 → 2026년 110건대), 이 증가가 파마리서치 물량인지 신규 업체 진입인지는
구분되지 않는다. **등급을 A 로 올리려면 분기 실적과의 회귀(`report.py leadlag`) 통과가 필요하다.**

## 외부 리서치와의 교차검증 (유진투자증권 / KITA)

유진투자증권이 같은 아이디어를 **HS 3304.99.9000(10단위)** 로 추적한 리포트가 있다.
출처는 KITA(무역협회 K-stat). 이 파이프라인의 6단위 수집값과 대조한 결과:

| 연도 | 유진 10단위 | 본 수집 6단위 | 10/6 비중 | 잔차(비필러) |
|---|---|---|---|---|
| 2020 | $0M | $2.9M | 0% | $2.9M |
| 2021 | $1M | $4.1M | 24% | $3.1M |
| 2022 | $3M | $6.6M | 45% | $3.6M |
| 2023 | $16M | $20.2M | 79% | $4.2M |
| 2024 | $25M | $33.4M | 75% | $8.4M |
| 2025 | $77M | $85.3M | 90% | $8.3M |
| 2026 1–7월 | $74M | $77.6M | 95% | $3.6M |

세부 구간은 거의 정확히 일치한다 — **2026-Q2: 유진 $39M vs 본 수집 $40.7M (+4.4%),
2026-07: 유진 $15M vs $14.8M (−1.5%)**. 수집 파이프라인이 옳게 동작함을 외부 소스가 확인해 준다.

### 한계 — 관세청 API는 HS 6단위가 상한

```
HsSgn=3304999000 → resultCode 99 "품목코드는 6자리로 입력해야 합니다"
```

10단위 지역 데이터는 관세청 OpenAPI로 **불가능**하다. KITA K-stat을 써야 한다.
리포트가 10단위를 쓸 수 있는 이유가 그것이다.

### 대안 — 혼입 상수 보정

330499(6단위)에는 목표 코드(3304.99.9000) 외에 형제 코드 3304.99.1000/2000/3000이 섞인다.
그 혼입분이 시간에 대해 대체로 일정하므로 상수로 빼면 레벨 정확도가 회복된다.

```python
from kortrade import kpi
raw = kpi.export_proxy(store, "강릉시", ["330499"])
print(kpi.estimate_baseline(raw, before="2023-01"))
# → baseline_usd_month 351,625 / cv 0.78 / '상수 가정 타당'

adj = kpi.export_proxy(store, "강릉시", ["330499"], baseline_usd=470_000)
```

보정 효과 (유진 10단위 대비 오차):

| 연도 | 보정 전 | 보정 후 |
|---|---|---|
| 2023 | +26% | −9% |
| 2024 | +34% | +11% |
| 2025 | +11% | **+3%** |

`estimate_baseline()` 은 변동계수(cv)를 함께 반환한다. **cv가 크면 추세를 상수로 오인하는
것이므로 보정을 쓰면 안 된다** — 그 판정을 함수가 직접 내려준다.

### 분석 시작 구간 권고: 2023-01 이후

10단위 비중이 2020년 0% → 2023년 79% → 2026년 95%로 **계속 상승**한다.
2022년 이전 구간은 목표 기업의 기여가 거의 없어, 회귀에 넣으면 관계를 왜곡한다.
`companies.yaml` 의 `analysis_start: "2023-01"` 이 그 기준이다.

### 프록시 커버리지 ≈ 52%

2025년 강릉 수출 $77M ≈ 1,060억원 vs 파마리서치 해외 매출 약 2,050억원(리포트 차트).
**프록시는 해외 매출의 절반 정도만 잡는다.** 나머지는 현지법인 매출·기술료·타 생산지다.
따라서 레벨을 그대로 매출로 환산하면 안 되고, **YoY·가속 등 변화율로 써야 한다.**
`kpi_coverage_ratio: 0.52` 로 기록해 두었다.

### ★ 제조장소 기준의 현실 — 프록시 해석을 바꿔야 한다

**서울 강남구가 전국 1위($1.44B)다.** 강남에 화장품 공장은 없다.
API 설명문은 "수출은 「제조장소 우편번호」 기준"이라고 하지만, 실무에서는 수출신고서의
제조장소란에 **본사 주소를 적는 경우가 많다.** 즉 이 데이터는 공장 위치가 아니라
**"수출신고서에 기재된 주소"** 다. ODM 생산품이 브랜드사 본사 구로 잡히는 이유다.

함의:
- 강남·송파·마포·용산 같은 **브랜드사 밀집 지역** = 브랜드사 수출 프록시 (공장 아님)
- 화성·음성·세종 같은 **공단 지역** = ODM 제조사 프록시
- 강릉처럼 **본사와 공장이 같은 도시** = 가장 깨끗한 케이스

`companies.yaml` 에 기업을 추가할 때 "공장이 어디냐"가 아니라
**"수출신고를 어느 주소로 하느냐"** 를 물어야 한다.

## 행정구역 개편 — 자동 병합 (2026-07 실측)

시군구 코드를 API가 주지 않아 **이름**으로 키잉하므로, 개편이 일어나면 시계열이 끊긴다.

```
인천광역시 중구      2025-01 ~ 2026-06   (2026-06 $119M)
인천광역시 제물포구   2026-07 ~            (2026-07 $140M)   ← 같은 실체
인천광역시 서구  →  서해구  도 동일 (2026-07)
```

보정 없이 보면 인천 중구는 **3M YoY −47% 급감**으로 보인다. **가짜 신호다.**

시도 레벨도 같다 — 코드 29(광주)·46(전남)은 2026-06까지만 응답하고,
코드 12(전남광주통합특별시)가 2026-08부터 응답한다.

대응:

```python
# 개편 전후를 한 계열로 자동 병합 (기본 동작)
s = kpi.export_proxy(store, "중구", ["330499"], sido="인천광역시")   # 20개월, 끊김 없음
s2 = kpi.export_proxy(store, "제물포구", [...], sido="인천광역시")   # 동일 계열 반환

# 설정에 없는 개편을 데이터에서 자동 탐지
regions.detect_boundary_changes(store)
# → 인천광역시 중구(2026-06) → 제물포구(2026-07)  규모비 1.31  확신도 높음
```

같은 이름이 여러 시도에 있으므로(중구·서구 등) **시도를 함께 보고 매칭**한다.
서울 중구는 영향을 받지 않는다. 매핑은 `config/regions.yaml` 에 있고,
모든 항목은 **실측 근거(evidence)를 달아야 통과**하도록 테스트로 강제한다.

## 한계와 주의

1. **ODM/유통사는 잡히지 않을 수 있다.** 수출신고인이 브랜드사면 제조장소 기준 집계와
   어긋난다. 실리콘투 같은 유통사는 레이어 2가 아니라 레이어 1(섹터)로 대응해야 한다.
2. **HS 코드 ≠ 제품.** 같은 6단위에 이종 제품이 섞인다. 반드시 `purity` 진단을 거칠 것.
3. **금액은 FOB 달러 기준.** 원화 매출과 비교할 때 환율이 별도 변수로 들어간다.
   YoY 기반으로 회귀하면 레벨 효과는 줄지만 환율 변동 구간에서는 잔차가 커진다.
4. **2026-07-01 지방행정체계 개편**(전남광주 통합, 인천 개편)으로 시도코드가 바뀌었다.
   `bootstrap_codes.py --post 202608` 로 개편 후 표를 별도 생성해야 시계열이 끊기지 않는다.
5. `companies.yaml` 의 공장 소재지는 **1차 출처로 검증된 것만 `verified: true`** 로 둔다.
   현재 검증 완료: 한국콜마(세종·부천). 미검증 항목은 사업보고서로 확인 후 승격할 것.
